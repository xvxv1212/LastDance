# 권리채비 RAG 근거 묶음 준비 작업

상태: 코드 검토용 / 작성일: 2026-11-17 / 담당: 이형민

## 변경 내용

- 날짜 문맥이 명확한 유효 ISO 날짜는 개인정보 마스킹에서 보존한다. 명시된 계좌·입금·송금 번호와 모호한 번호는 계속 마스킹한다. 자유 입력의 날짜 모양 문자열 전체를 무조건 예외 처리하지 않는다.
- `ApprovedEvidenceReader` 포트를 추가하고 기존 `ApprovedKnowledgeBase.evaluate()`의 승인 결과와 거절 이유를 사용한다. 승인 영수증·본문·출처 검증은 기존 구현을 유지한다.
- `PrepareEvidencePacket`은 직접·연결 근거를 최대 깊이 2, 최대 20건으로 조회한다. 연결표는 서버 관리 설정이며 시민 요청이나 모델 출력을 연결표로 사용해서는 안 된다. 순환은 중복 방문 없이 종료한다. 모든 연결을 필수로 취급하며 미승인·누락·상한 초과는 보류 사유를 남긴다.
- 승인된 원문과 구조화된 시행일을 분리해 날짜가 계좌번호 마스킹으로 변형되는 것을 방지한다. 본문에 민감정보가 감지되면 해당 자료를 전송 후보에서 제외한다.
- 같은 점검·같은 확인자의 확인 사실만 후보 묶음에 넣고, 사용자가 모름 처리한 사실은 UNKNOWN/null로 보존한다. 상충 사실과 중복 사실 키는 보류한다.
- 사용자 입력 6,000자, 근거 6,000자, 직렬화된 전체 묶음 10,000자를 각각 검사한다. 초과 시 본문을 잘라 통과시키지 않는다. 이 값은 문자 예산이며 실제 모델 토큰·시스템 지시문·출력 예약 예산은 후속 호출 어댑터에서 추가 검증해야 한다.

## 실행 경계

이 코드는 **백엔드 내부의 전송 준비 모듈**이다. API·LangGraph·UoW 조회와 자동으로 연결되지 않으며 외부 모델을 호출하지 않는다. 호출자는 먼저 기존 점검 소유권 검사를 수행한 뒤 해당 점검의 사실만 전달해야 한다. 현재는 생성 허용이 항상 false이며, 사건 적용 시점과 의미적 충분성의 미검토 상태를 유지한다. 필요한 사실 목록은 서버의 작업별 규칙으로 지정해야 한다.

기존 `candidate_extract` 모델 어댑터는 사실 후보 추출 전용으로 보존한다. RAG 보고서 단계의 출력 스키마, 동의·철회 검사, 감사 기록, 생성 후 인용검사는 아직 연결하지 않았다. 원문 승인이나 UNKNOWN을 변경하지 않았으며 DB DDL·적재·벡터 변경도 없다.

v0.4의 23개 후보 자료를 승인하거나 적재하지 않았다. 실제 자료를 연결하려면 기존 승인 기록과 원문 증빙을 준비하고, 관계의 출처·필수성·자료 유형 정책을 확인해야 한다. 관계가 없다는 빈 연결표를 필수 근거가 없다는 검증 결과로 간주하지 않는다.

## 후속 작업

검증 결과: Python 3.11.9 전체 시험 243 통과·22 건너뜀(34.07초), 신규 시험 18개 포함.
Python 3.14 보조 환경에서도 243 통과·22 건너뜀을 확인했다. 두 실행 건수를 합산하지 않는다.
Ruff 전체 검사 통과. PostgreSQL 등 건너뛴 시험은 통과로 집계하지 않는다.
실행 로그는 각 환경의 backend/var/rag_pytest*.log에 있으며 개인 로컬 검증 자료로 Git에 넣지 않는다.

1. 최신 main과 변경점을 비교하고 별도 PR 준비.
2. 승인 자료·연결표의 출처를 확인하고 사실 조회·소유권 검사에서 이 준비 모듈을 호출하는 경로 추가.
3. 작업별 필수 사실·근거·적용 시점 규칙과 별도 RAG 출력 계약 구현. 법률 결론·확정 환불액은 허용하지 않는다.
4. 기존 외부 전송 동의·철회·마스킹·전체 예산·감사·출력 검증을 모두 거친 뒤 제한된 모델 시험.

에이전트 반복 검색 및 실제 유료 호출은 이번 작업에 포함하지 않았다.

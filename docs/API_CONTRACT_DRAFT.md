# API 인터페이스 계약 초안

- 상태: **초안 / 팀 미승인**
- 프로젝트: 권리채비 AI (헬스장·필라테스 중도해지·환불 MVP)
- 원칙: 구현된 엔드포인트와 제안 엔드포인트를 구분한다.

## A. 구현되어 있는 API (기존 ZIP에서 유지)

### `GET /health`

- 목적: 웹 서버 프로세스 상태 확인 (DB/LLM 정상 여부를 보장하지 않음)
- 성공 `200`: `{"status": "ok"}`

### `POST /api/contracts/extract-text`

- 요청: `multipart/form-data`, `file` (PDF)
- 성공 `200` 예시:

```json
{
  "filename": "contract.pdf",
  "page_count": 1,
  "has_text": true,
  "pages": [{"page": 1, "text": "계약서에서 추출된 문자열"}]
}
```

- `400`: PDF 파일 서명 불일치·손상·암호화 등
- `413`: 크기 또는 페이지 수 제한 초과
- `422`: 파일 누락 등 요청 형식 오류
- 디폴트 제한: 10 MiB 및 30페이지. 스캔본 OCR은 수행하지 않는다.
- 서버는 이 API에서 원본 PDF를 영구 저장하지 않는다.
- 응답의 `text`는 원문 추출 **결과**이며 승인된 사실이나 법적 판단이 아니다.

## B. 이후 구현 제안 — 현재 호출 불가

아래 경로·메서드·필드명은 아직 확정되지 않았고 프론트엔드에서 사용하면 안 된다.

| 후보 기능 | 제안 경로 | 확인해야 할 계약 |
| :-- | :-- | :-- |
| 상담 사례 생성 | `POST /api/cases` | 동의, 개인 정보 최소 수집, 사례 ID |
| 사실 후보 목록 | `GET /api/cases/{case_id}/facts` | 근거 위치, 확신도 표현, 미확인 표시 |
| 사실 정정·승인 | `POST /api/cases/{case_id}/facts/confirm` | 승인자, 버전, 정정 이력, 동시 수정 충돌 |
| 근거 비교 요청 | `POST /api/cases/{case_id}/review` | 승인된 스냅샷 필수, 근거 출처·기준일 |
| 보고서 조회 | `GET /api/cases/{case_id}/report` | 확인 사실·주의·추가 확인 분리 |

## C. 팀 합의 체크포인트

1. 화면별 데이터 소유자, 상태값, 오류 처리, 비동기 처리 여부
2. 개인정보 수집 동의·보존 기간·삭제 방법 (미확정)
3. `후보 사실`과 `사용자가 확인한 사실`을 절대 혼용하지 않는 데이터 설계
4. 공식 근거의 출처 URL/발행 기관/적용 범위/기준일/검증 상태
5. API 계약 변경 시 문서·프론트·백엔드 테스트를 한 PR에서 함께 업데이트
